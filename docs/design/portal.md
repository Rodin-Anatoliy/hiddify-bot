# Портал и инвайт-коды — проект

Статус: **проект; этап 1 (коды в боте) написан 2026-10-01** (2026-09-28 — проект). Решения после обсуждения — в `docs/decisions.md`.
В этом файле нет адресов сервера и секретов: репозиторий публичный. Домен панели ниже — `<домен>`.

> Разделы 2–5 и этапы 2–5 из раздела 6 описывают целевой проект с веб-порталом. Что этап 1 делает на самом деле — в разделе 6.1; в местах, которые теперь расходятся с кодом, стоит пометка «(в этапе 1: …)».

## 1. Зачем

Сейчас новый человек пишет боту → жмёт «Запросить подключение» → Анатолий вручную одобряет → бот создаёт пользователя в панели. Минусы: ручная работа; человеку без VPN нужен Telegram, чтобы вообще начать; новый пользователь в Hiddify v13 работает не на всех профилях сразу (раздел 6).

Цель:
- Анатолий выдаёт **инвайт-код** в боте, дальше всё автоматически.
- Код гасится **на веб-странице без VPN** или **в боте** — логика одна.
- Страница пользователя: одно приложение под его устройство, кнопка «Добавить подписку», 3 шага.
- **Объявления** видны и в Telegram, и на странице (когда VPN лежит, а сервер доступен).

## 2. Сценарии

### 2.1 Выдача кода (Анатолий, бот)
1. `/invite` → два шага кнопками: **кому** («Свой» / «Знакомый») → **срок** («Бессрочно» / «День» / «Неделя» / «Месяц» / «Полгода»). У каждого типа срок по умолчанию выделен — обычно достаточно двух нажатий.
2. Бот отвечает: код (например `K7QM-4XTP-9A`) и готовый текст для пересылки:
   ссылка `https://<домен>:8443/?code=K7QM-4XTP-9A`, альтернатива — «или напишите боту @… и введите код», срок действия кода. *(В этапе 1: код вида `K7QM4-XTP9A`, веб-ссылки нет — только `t.me`-ссылка и кнопка «У меня есть код»; см. 6.1.)*
3. `/invites` — список активных кодов, кнопка «Отозвать».

Тарифы (D3, D4):
- **Свой** — трафик без ограничений (как сейчас: 100000 ГБ); срок по умолчанию — бессрочно (10000 дней).
- **Знакомый** — 200 ГБ в месяц со сбросом (`mode=monthly`); срок по умолчанию — бессрочно.
- Срок можно выбрать у любого типа: день / неделя / месяц / полгода / бессрочно.
- **Пробный день** — не тариф в коде, а старт после погашения на странице: 1 день, 5 ГБ.

Код: одноразовый; срок годности — 7 дней: не погасили за неделю — код сгорает (D4); тариф внутри кода. В базе храним **хэш** кода (SHA-256), не сам код — утечка базы не даёт живых кодов.

### 2.2 Погашение на странице (без VPN)
1. Человек открывает ссылку `…/?code=XXXX` → поле кода уже заполнено → «Активировать».
   Открытие ссылки код **не гасит** — гасит только нажатие кнопки (POST). Иначе код сжёг бы сам Telegram: он открывает ссылки, чтобы построить превью. Код в адресе — это нормально: он одноразовый и живёт 7 дней.
2. Сервер: проверка кода и лимита попыток → выдаёт пользователя Hiddify с **пробным доступом на 1 день** → код помечен «погашен».
3. Переход на личную страницу `https://<домен>:8443/u/<токен>` (токен случайный, 128 бит, не UUID; страницу можно сохранить в закладки).
4. На странице — кнопка **«Привязать Telegram»**: ссылка `https://t.me/<бот>?start=b_<токен привязки>`. Бот по метке привязывает telegram_id и **включает тариф из кода**.
5. Не привязал за сутки — пробный доступ кончается (панель сама выключает пользователя по сроку), код уже сгорел. Выдать новый — только новым кодом.

Подписка одна: ссылка не меняется, при привязке тот же пользователь панели продлевается до тарифа — в приложении ничего переделывать не надо.

**Чтобы пробный день не приняли за постоянный доступ** (напомнить в боте нельзя — Telegram ещё не привязан):
- на странице — крупная плашка «Доступ на сутки. Привяжите Telegram, иначе отключится» с обратным отсчётом, кнопка привязки — главная;
- имя пользователя в панели на время пробы — «Пробный — привяжите Telegram»; после привязки — нормальное. Если Hiddify отдаёт имя в заголовке `profile-title`, приложение покажет его как название подписки (проверить, п. 7.7);
- приложение само показывает остаток дней и трафика из заголовка `subscription-userinfo` (Hiddify его отдаёт — проверить там же).

### 2.3 Погашение в боте
`/start` → кнопка «У меня есть код» → ввод кода → тот же сервис погашения. Telegram уже известен, поэтому **тариф включается сразу**, без пробного дня. Бот присылает ссылку на личную страницу (там инструкция по установке). *(В этапе 1: после погашения в боте человек получает ссылку подписки; личной страницы ещё нет.)*

### 2.4 Личная страница
- Страница одна на всех: один шаблон в программе; по токену из адреса программа подставляет данные нужного человека. Ничего под каждого пользователя не создаётся. Ссылка на личную страницу секретна так же, как ссылка подписки.
- Определяем устройство по User-Agent: iOS / Android / Windows / macOS / Linux; показываем **одно** приложение — Hiddify (ссылка в магазин / на релиз), рядом мелкая ссылка «другое устройство».
- 3 шага:
  1. Установить приложение (кнопка магазина).
  2. **«Добавить подписку»** — deep link `hiddify://import/<ссылка подписки>#<имя>` + запасной вариант «скопировать ссылку».
  3. В приложении выбрать группу **`lowest`** (картинка-подсказка) — иначе приложение делает round-robin (vpn-ops D10).
- Статус: тариф, до какого числа, трафик (из API панели), привязан ли Telegram.
- Блок объявлений (последние 3).

### 2.5 Объявления
- `/announce <текст>` в боте → сохраняется в SQLite → рассылка в Telegram (существующий механизм `/broadcast` с его ограничением скорости) → показ на всех страницах портала, в том числе на стартовой (без кода).
- `/announce off` — снять активное объявление со страницы.
- Смысл: если лежат профили VPN, но сервер жив — люди открывают страницу без VPN и видят, что происходит. Если лежит весь сервер — страница тоже недоступна (честное ограничение).

### 2.6 Ручное подтверждение
Кнопка «Запросить подключение» и одобрение Анатолием **убираются** после запуска кодов. Незнакомцу без кода бот отвечает «Попросите код у администратора» (кнопка «Написать в поддержку» остаётся). *(В этапе 1 кнопка «Запросить подключение» уже убрана.)*

## 3. Как устроено

### 3.1 Один бинарник, один сервис
- В `cmd/bot` рядом с long polling запускается HTTPS-сервер на `:8443` (порт — в env `PORTAL_ADDR`). Общие сервисы, общая SQLite, общий `context` для остановки.
- Если портал не стартовал (порт занят, нет сертификата) — **бот работает дальше**, в лог и админу — ошибка. Паника в обработчике портала не роняет бота (`recover`).
- Страница — статические файлы и шаблоны, вшитые через `//go:embed` (без JS-фреймворков, один CSS). systemd-сервис тот же, деплой тот же.
- Не через haproxy/nginx Hiddify — свой порт, свой TLS.

### 3.2 Сертификат
- Берём сертификат `<домен>` из каталога SSL Hiddify **только на чтение** (пути — в env `PORTAL_CERT`, `PORTAL_KEY`).
- `tls.Config.GetCertificate` с кэшем: раз в час (и при ошибке) проверяем время изменения файлов и перечитываем → продление acme.sh подхватывается без перезапуска.
- Бот сейчас работает от root, поэтому чтение ключа возможно. Но root-процесс, открытый в интернет, — риск (раздел 8).

### 3.3 Пакеты (по слоям, как сейчас)
- `internal/domain/invite` — код, тариф, статусы.
- `internal/service/invite` — выдача, погашение (общее для бота и веба), привязка, объявления. *(В этапе 1: это файл `internal/service/invite.go` в пакете `service`, не отдельный пакет.)*
- `internal/repository/sqlite` — новые таблицы, миграция.
- `internal/transport/tg` — `/invite`, `/invites`, `/announce`, «У меня есть код», `/start b_<токен>`.
- `internal/transport/web` — HTTP-обработчики, лимит попыток, шаблоны, `embed`.

### 3.4 Данные (SQLite, новые таблицы)
- `invites`: id, code_hash, tariff (unlimited|temporary), days, limit_gb, expires_at, created_at, revoked_at, redeemed_at, redeemed_uuid. *(В этапе 1: колонки `kind` ('own'|'friend') и `days` вместо `tariff`/`limit_gb`, плюс `claimed_at`, `claimed_by_tg`; время — Unix-секунды.)*
- `portal_users`: hiddify_uuid, page_token_hash, bind_token_hash, bind_expires_at, invite_id, telegram_id (после привязки), trial_until, tariff_applied_at.
- `announcements`: id, text, created_at, active.
- Лимит попыток — в памяти (сбрасывается при перезапуске, это допустимо).

### 3.5 Вызовы API панели
Используем только то, что уже есть в клиенте: `POST/GET/PATCH /<admin_proxy>/api/v2/admin/user/…`. Пробный день — `package_days=1`, `start_date=сегодня`; тариф — PATCH `package_days`, `usage_limit_GB`, `start_date`, `telegram_id`. Ключ API — только в `.env` на сервере, в браузер не уходит никогда: страница видит лишь свою ссылку подписки.

## 4. Безопасность
- Код: 10 символов алфавита Crockford base32 (без 0/O/1/I) ≈ 50 бит *(в этапе 1: алфавит Crockford-подобный — в нём есть 0 и 1; при вводе O→0, I/L→1)* — перебор бессмысленен даже без лимитов.
- Лимит попыток: на IP — 5 неверных за 10 мин, потом блок на 1 ч; общий — 100 неверных в час на весь портал (дальше форма закрыта до конца часа, админу сообщение); в боте — 5 неверных на telegram_id за 10 мин.
- Погашение атомарно: одна транзакция `UPDATE invites … WHERE redeemed_at IS NULL` — дважды один код не пройдёт.
- Токены страницы и привязки — случайные 128 бит, в базе только хэши; токен привязки одноразовый, живёт до конца пробного дня.
- HTTP: только HTTPS; таймауты чтения/записи; тело запроса ≤ 4 КБ; заголовки `Content-Security-Policy`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` (ссылка с токеном не утекает); `robots: noindex`.
- В логах — ни кодов, ни токенов, ни UUID (только id записи).
- Ключ API панели и токен бота — только в `/opt/hiddify-bot/.env`.

## 5. Слабое место: `apply_users` в Hiddify v13

Как сейчас (проверено в vpn-ops 28.09, D15): при создании пользователя через API панель сама запускает `apply_users` (~10 с, связь у других не рвётся). После этого у нового пользователя работает xhttp (hiddify-core), а **tcp+reality «vodafone» (основной профиль, xray) — только после следующего полного Apply**: горячее добавление в xray пропускает этот прокси из-за регистра в имени тега. Полный Apply перезапускает xray — рвёт связь всем, включая ПК Анатолия.

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. Запас заранее созданных пользователей** | Бот держит 5–10 «пустых» пользователей (включены, без привязки). Анатолий раз в какое-то время делает обычный Apply в vpn-ops. При погашении кода бот берёт пользователя из запаса и меняет ему имя/срок/лимит через PATCH. Запас кончается — бот создаёт новых и пишет Анатолию «нужен Apply». | Новый пользователь работает на всех профилях сразу; бот не делает Apply | Нужно проверить, что PATCH не удаляет и не добавляет пользователя в xray заново (иначе та же проблема); «пустые» UUID в конфиге (секретны, никому не выданы — риск низкий); немного логики учёта запаса |
| **Б. Apply после создания** | Бот сам вызывает полный Apply панели | Просто | Рвёт связь всем при каждом новом человеке; бот лезет в настройки Hiddify (запрещено, это vpn-ops); Apply может упасть и уронить панель |
| **В. Как сейчас + напоминание** | Создаём при погашении; сразу работает xhttp; бот пишет Анатолию «N новых ждут Apply» | Ничего нового на сервере | Первые часы/дни новый человек сидит на запасном медленном профиле |
| **Г. Починить причину в vpn-ops** | Переименовать прокси 103 так, чтобы горячее добавление в xray работало (vpn-ops D15, отложено) | Проблема исчезает для всех путей создания | У всех пользователей меняется имя профиля; это решение vpn-ops, не бота |

**Решение (D5):** MVP — вариант **В**. Основной путь — **Г**: это штатная настройка Hiddify (переименование прокси в UI), делается в vpn-ops по их протоколу. **А** — только если Г окажется невозможен (он добавляет в бот свою логику поверх Hiddify). **Б — нет.**

## 6. План работ по боту

Каждый шаг — новый executor → reviewer → коммит → пуш только после «ок». Риск: «сервер» — действие на de-1 с «ок».

**Этап 0. База бота — привести в порядок (до любых новых функций).** Сейчас: 3 таблицы, миграции «CREATE IF NOT EXISTS + ALTER» при старте, без номера версии и без бэкапа.
- 0.1 Снимок: копия `bot.db` с сервера (сервер, только чтение, с «ок»; файл — в `reports/`, в git не попадает) → explorer/executor сверяют с панелью: привязки к удалённым в панели UUID, дубли, пользователи без UUID, telegram_id в панели ≠ в базе. Итог — список расхождений, без правок.
- 0.2 Миграции с версиями: таблица `schema_version`, пронумерованные миграции, каждая в транзакции; перед миграцией при старте — копия файла базы (`VACUUM INTO bot.db.bak-<версия>`). Тест: миграции на пустой базе и на копии из 0.1.
- 0.3 Правило «источник правды»: срок, трафик, включён ли — только в панели (бот не хранит копий); в базе бота — только связи (telegram_id ↔ UUID), поддержка, коды, объявления.
- 0.4 Чистка расхождений из 0.1 — отдельной командой админа или разовой миграцией, после «ок» по списку.

**Этап 1. Коды в боте (MVP-ядро).** Таблица `invites`; `/invite` (кому → срок → код + текст для пересылки); `/invites` + отзыв; «У меня есть код» → создание пользователя с тарифом (вариант В) + напоминание Анатолию про Apply. Уже убирает ручное одобрение.

**Этап 2. Подготовка сервера (сервер, с «ок»).** Сервис с root → отдельный пользователь (`deploy/`, права на сертификат и `/opt/hiddify-bot`), проверка, что бот работает; `ufw allow 8443/tcp`.

**Этап 3. Портал (MVP).** HTTPS :8443, сертификат с перечитыванием, `embed`, форма кода, лимиты попыток, личная страница (3 шага, deep link), пробный день.

**Этап 4. Привязка Telegram.** `/start b_<токен>` → тариф из кода; пробный день; убрать «Запросить подключение» *(в этапе 1 уже убрана)*; ссылка на личную страницу в `/status`.

**Этап 5. Объявления.** `/announce`, показ на страницах.

**Потом, если понадобится:** запас пользователей (только если D5-Г не выйдет), «Новая ссылка», предупреждение о большом расходе.

MVP = этапы 0–4.

## 6.1. Что реализовано в этапе 1 (2026-10-01)

Только бот, без веб-части. Где текст выше расходится с этим разделом — верно то, что здесь.

**Код.** 10 символов Crockford base32 (в нём есть 0 и 1; нет I, L, O, U), показывается как `XXXXX-XXXXX`. В базе только SHA-256 от нормализованного кода. При вводе: заглавные, без пробелов и дефисов, `O`→`0`, `I`/`L`→`1`. Живёт 7 дней. Время в таблице `invites` — Unix-секунды (миграция 2; внешних ключей нет).

**Тарифы.**
- «Свой» — 100000 ГБ, `mode=no_reset`; «Знакомый» — 200 ГБ, `mode=monthly`.
- Срок: день / неделя / месяц / полгода (1 / 7 / 30 / 180 дней) или бессрочно (10000, по умолчанию). Передаётся как `package_days` через тот же `CreateUser`, что и при одобрении заявки.
- `start_date` не передаём: в панели v13 отсчёт срока идёт с первого трафика, а не с создания (проверено по исходникам v13.0.3). Значит, неиспользованный пользователь не истекает. `start_date` в панели — дата (без времени), и пользователь активен, пока `package_days - (сегодня - start_date) >= 0`: «День» живёт день первого подключения и весь следующий календарный день (от 24 до 48 часов, по часовому поясу сервера), и любой другой срок тоже на сутки с небольшим длиннее номинала.

**Админ.**
- `/invite` → «Свой / Знакомый» → срок → код, срок действия и готовый текст: «Откройте ссылку и нажмите «Старт»: `https://t.me/<бот>?start=i_<КОД без дефиса>`. Если ссылка не открывается — откройте бота @<бот>, нажмите «🎟 У меня есть код» и отправьте код: <КОД>». Без веб-ссылок. Кнопка «Переслать» открывает `https://t.me/share/url?url=…&text=…` (выбор чата).
- `/invites` — активные коды (тип, срок, до какого числа; самого кода нет, хранится только хэш), у каждого «Отозвать».
- После успешного погашения админу приходит сообщение: кто, тариф и напоминание «нужен Apply в панели: новый пользователь сначала работает только на запасном профиле» (D5, вариант В). Бот Apply не вызывает.

**Погашение** (`/start i_<КОД>` или код сообщением; обе дороги — один сервис `InviteUseCase.Redeem`). Всё под одним мьютексом: двойное нажатие не даст двух вызовов `CreateUser`.
1. Человек уже привязан (есть UUID) → «у вас уже есть подписка»; код не занимается и не считается ошибкой.
2. Неверные попытки: не больше 5 на telegram_id за 10 минут (в памяти); дальше отказ без обращения к таблице кодов, пока окно не пройдёт. Неверный = код не найден, просрочен, отозван, уже погашен, занят другим, или не похож на код. Ответ один и тот же.
3. Код занимается одним `UPDATE … WHERE redeemed_at IS NULL AND revoked_at IS NULL AND expires_at > now AND (claimed_at IS NULL OR claimed_by_tg = я)`. Ноль строк → «код недействителен».
4. Ищем пользователя панели по telegram_id.
   - Есть, и это повторная попытка того же человека (занял код раньше, ответ потерялся) → достраиваем на этом UUID, второй раз не создаём.
   - Есть, а раньше код не занимали → код освобождается, отказ (D2).
   - Поиск упал → `CreateUser` не зовём; если код занят только что — освобождаем.
5. Нет → `CreateUser` с тарифом. Чёткий отказ панели (4xx, кроме 404/408/429) → код освобождается, «напишите в поддержку». Таймаут, 5xx, сеть, пустой UUID → код остаётся занятым, «попробуйте ещё раз через минуту». Успех → локальный пользователь (`LinkSource=invite`, `CanMessage=true`), код погашен, человеку уходит ссылка подписки.
6. Если сохранить локального пользователя не вышло — код остаётся занятым; повтор найдёт пользователя панели и закончит.

**Меню.** Для непривязанного вместо «Запросить подключение» — «🎟 У меня есть код» (следующее сообщение 10 минут считается кодом) и «📨 Написать в поддержку». Свободный текст считается кодом только после этой кнопки; иначе он уходит в поддержку как раньше. Обработчики одобрения/отклонения заявок остались: старые кнопки в чате админа работают.

**Известные края.** Если после таймаута панели человек до повтора нажмёт обычный `/start` или напишет любое сообщение в поддержку, автопривязка привяжет его к уже созданному пользователю панели (`LinkSource=auto`). Код при этом останется «ожидает завершения» до истечения срока, админу напоминание про Apply не придёт (подписка работает). Занятый код освободит только отзыв и выпуск нового.

Повтор того же человека в пределах 60 секунд от предыдущей попытки получает «попробуйте через минуту» без обращения к панели (панель может ещё доделывать создание пользователя); ранние повторы отсчёт не продлевают. Осознанный компромисс: если панель не отвечает дольше 60 секунд и повтор после окна не видит созданного пользователя, будет второй `CreateUser` (максимум один новый на окно); такой дубль админ увидит в панели и удалит вручную.

## 8. Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| 8443 или IP/домен блокируются мобильными операторами | Страница без VPN бесполезна для части людей | Проверка 7.1 до начала этапа 2; погашение в боте работает всё равно |
| Бот от root открыт в интернет | Уязвимость в обработчике = root на сервере с VPN | Минимальный код, лимиты, таймауты; вместе с порталом сервис переводится на отдельного пользователя с доступом только к сертификату и своим файлам (D4) |
| Утечка ссылки с кодом | Чужой гасит код первым | Коды одноразовые и с коротким сроком; `/invites` → отзыв; видно, кто погасил |
| Портал падает вместе с ботом (один процесс) | Пропадают оба | `recover`, портал не обязателен для старта бота, `Restart=on-failure` |
| Продление сертификата | Портал отдаёт просроченный серт | Перечитывание по времени изменения файла + предупреждение админу за 7 дней до конца срока |
| Вариант В: новый человек на xhttp до Apply | Медленнее, YouTube может не работать | Напоминание Анатолию; дальше — вариант А или Г |
| Бесплатный домен no-ip не продлён вовремя (раз в месяц вручную) | Ломаются сразу портал, сертификат и ссылки подписок у всех | Не зона бота; покупка домена — вопрос для vpn-ops (backlog) |
| Изменения в Hiddify (обновление v13.x) меняют API | Погашение ломается | Тесты клиента на `httptest`; перед обновлением Hiddify — проверка в vpn-ops |

## 9. Злоупотребления (исследование 2026-09-28)

- **Лимита устройств в Hiddify v13 нет:** поле «Max IPs» есть, но проверка закомментирована (`hiddifypanel 13.0.3, models/user.py`); запрос открыт годами (Hiddify-Manager #3490, #4711). HWID-лимит (Remnawave, заголовок `x-hwid`) приложение Hiddify не поддерживает (hiddify-app #1957). Самим ограничивать устройства — не делаем: мобильные IP меняются, семья сидит за одним IP.
- **Защита — тарифом:** своим — без ограничений; знакомым — 200 ГБ/мес со сбросом: утёкшая ссылка быстро упрётся в лимит и не помешает остальным.
- **Торренты** — главный реальный риск (жалобы хостеру). Встроенной блокировки в Hiddify v13 нет (#4712); есть самодельный рецепт — правило `bittorrent → blackhole` в шаблонах xray, ловит не всё и может слететь при обновлении. Это настройка сервера → задача для vpn-ops, не для бота.
- **Потом, если понадобится:** кнопка «Новая ссылка» (перевыпуск подписки, старая умирает) и дневное предупреждение админу о большом расходе.
- Норма у коммерческих ботов: пробный период 1–3 дня / ~10 ГБ, один на telegram_id, привязка через `t.me/<бот>?start=<метка>` — совпадает с нашим проектом.

## 11. Незаметность портала (предложение 2026-09-28, ждёт «ок»)

Порт 8443 — отдельный сервер бота, маскировка Reality на него не распространяется. Сертификат и связка «домен ↔ IP» и так публичны (логи сертификатов, DNS), поэтому палит не порт, а **содержимое**: сканеры (Shodan/Censys, активные проверки ТСПУ) заходят на `/` и видят страницу «введите код VPN».
- `/` и любой неизвестный адрес — нейтральная заглушка или 404, без слов о VPN. Форма — только при ссылке с **действующим** кодом (проверка при открытии без погашения; неверный код — та же заглушка и +1 к счётчику неудачных попыток), личная страница — только с верным токеном. Отдельной страницы для ручного ввода кода нет: у кого только код — вводит в боте.
- Защита портала — своя (haproxy/nginx Hiddify перед ним не стоят): коды ~50 бит и токены 128 бит не подобрать; лимиты попыток (раздел 4) считают и открытия страниц; ответы на неверное — одинаковые и дешёвые. Капчу не ставим: сторонние капчи в РФ работают плохо и сами «светят» сервис.
- Тексты нейтральные: «Приглашение», «Подключение», без «VPN», «обход», «блокировки» (в РФ запрещена популяризация способов обхода). Подробности — в боте.
- Объявления — только на личной странице (за токеном), не на общей.
- Не индексировать: заголовок `X-Robots-Tag: noindex, nofollow`, `robots.txt` — запрет всего, ссылок на портал нигде публично нет.
- Проверить до этапа 3: **родная страница пользователя Hiddify** (открывается по ссылке подписки на домене панели, уже без VPN): что на ней есть (приложения по устройству, кнопка импорта, остаток дней/трафика, объявления?). Если хватает — портал сокращается до «погасить код + привязать Telegram» и дальше отправляет на родную страницу (D5: по возможности — штатные функции Hiddify).
